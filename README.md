# 영화 예매 모니터

CGV / 메가박스의 **예매 오픈**과 **취소표(빈자리)** 를 감지해 Discord·텔레그램으로
알림을 보내주는 도구.

알림만 받고 직접 예매해도 되고, 켜두면 **좌석 선점과 카카오페이 결제요청까지
자동으로** 진행합니다 (`auto_book` / `auto_pay`). 최종 결제 승인은 항상 사용자가
폰에서 직접 합니다.

## 동작 방식

CGV / 메가박스 API를 주기적으로 폴링(분당 최대 N회, 설정 가능)하며,
타겟마다 두 가지 모드 중 하나로 동작합니다.

**`mode: open` — 예매 오픈 감시 (기본값)**

지정한 날짜 중 **아직 안 열린 가장 빠른 날짜 하나**만 붙잡고 봅니다.
오픈은 빠른 날짜부터 순서대로 열리므로, 뒤쪽 날짜를 미리 볼 이유가 없습니다.

1. 커서를 잡는다 — 감시 날짜 중 아직 확인이 안 끝난 가장 빠른 날짜
2. 매 바퀴 그 날짜 **하나만** 조회 (날짜를 몇 개 적든 바퀴당 1회)
3. **직전 바퀴엔 회차가 없었는데 이번 바퀴엔 있으면** 오픈으로 판단 →
   `@here` 알림, `auto_book`이면 곧바로 예매
4. 그 날짜는 확인 완료로 접고 커서를 다음 날짜로 옮겨 계속 감시

날짜를 전부 훑으면 미오픈 날짜 수만큼 요청이 나가고 한 바퀴가 길어져,
정작 열리는 순간을 늦게 잡습니다. 오픈런은 몇 초로 갈리므로 이쪽이 유리합니다.

오픈 판정을 "스케줄이 있다"가 아니라 **상태 전이**로 하는 이유가 있습니다.
있다는 사실만으로 판정하면 재시작할 때마다 이미 열려 있던 날짜를 오픈으로
오인해 표를 사버립니다. 그래서 **처음 본 날짜가 이미 열려 있으면 예매하지 않고
넘어갑니다.** 이미 열린 날짜의 빈자리는 취소표 타겟이 담당합니다.

판정 기준은 반드시 **필터를 통과한 회차**입니다. "그 날짜에 스케줄이 하나라도
있으면 열린 것"으로 보면 안 됩니다. CGV는 날짜를 통째로 열지 않고 특별
상영(GV·콘서트 실황 등)만 먼저 걸어두는 **부분 오픈**을 하기 때문입니다.

```
영등포 08/26  7관 산산조각 / 8관 경주기행 …  8회차  ← IMAX 정규 편성은 아직 없음
용산   08/28  18관 사진의 얼굴(GV)          1회차
압구정 08/30  씨네드쉐프 아트&다이닝          1회차
```

이 상태를 오픈으로 보면 그 날짜를 건너뛰어 **정작 원하는 회차가 열리는 순간을
놓칩니다.** 그래서 조건에 맞는 회차가 나올 때까지는 미오픈으로 두고 계속 봅니다.

같은 이유로 `dates`를 손으로 나눌 때 `fetch_screening_dates`(극장 상영일 목록)를
"어디까지 열렸나"의 근거로 쓰면 안 됩니다. 그 목록에는 상영관·영화 구분이 없어서,
IMAX가 아직 안 열린 날짜도 열린 것처럼 보입니다.

**`mode: cancel` — 취소표 감시**

1. 조건에 맞는 회차의 잔여 좌석을 계속 추적
2. 빈자리가 새로 생기면 알림 (같은 자리로 중복 알림하지 않음)
3. 종료하지 않고 계속 감시

CGV는 좌석 배치도까지 조회하므로 **특정 열 / 번호 / 연석 조건**을 걸 수 있습니다.
메가박스는 잔여 좌석 "수"로만 감시합니다.

## 설정

`config.yaml`을 편집합니다.

```yaml
max_requests_per_minute: 30

notifications:
  discord_webhook_url: "https://discord.com/api/webhooks/..."

targets:
  # 예매 오픈 감시
  - name: "용산 IMAX 헤일메리 4/20"
    type: cgv
    site_no: "0013"
    date: "20260420"
    screen_filter: "IMAX"
    movie_filter: "헤일메리"

  # 취소표 감시 (날짜 전체 + 요일별 시간대 + 좌석 위치)
  - name: "용산 IMAX 오디세이 취소표"
    type: cgv
    site_no: "0013"
    dates: all
    screen_filter: "IMAX"
    movie_filter: "오디세이"
    mode: cancel
    time_rules:
      weekday: ["19:00", "23:59"]
      weekend: ["12:00", "20:00"]
    seats:
      rows: ["K", "L", "M", "N"]
      seat_no: [16, 29]
      min_consecutive: 2
```

| 필드 | 설명 |
|------|------|
| `name` | 알림에 표시될 이름 (자유롭게 작성) |
| `type` | `cgv` 또는 `megabox` |
| `site_no` | CGV 영화관 코드 |
| `branch_no` | 메가박스 지점 코드 |
| `date` | 확인할 날짜 하나 (YYYYMMDD) |
| `dates` | `all` 또는 날짜 목록. `date` 대신 사용 |
| `screen_filter` | 상영관 타입 (IMAX, DOLBY, 4DX, SCREENX 등) |
| `movie_filter` | 영화명 키워드 (일부만 적어도 매칭) |
| `mode` | `open`(기본) 또는 `cancel` |
| `time_range` | 감시할 회차 시작시간 범위 `["18:00", "23:59"]` (선택) |
| `time_rules` | 평일/주말을 나눠 시간대를 지정 (선택, `time_range`보다 우선) |
| `repeat_alert_sec` | 자리가 열려 있는 동안 다시 알릴 주기(초). 생략하면 1회만 |
| `auto_book` | 크롬을 몰아 좌석 선점 → 결제수단 화면까지. 기본 꺼짐 |
| `auto_pay` | 카카오페이 결제요청까지 (승인은 폰으로 직접). 기본 꺼짐 |
| `kakaopay` | 카톡결제로 보낼 휴대폰번호·생년월일. 없으면 QR결제 |
| `pay_timeout_sec` | 승인 대기 시간(초, 기본 240). 지나면 초기 화면으로 이탈 |
| `auto_book_once` | **결제 완료 시** 그 타겟 감시를 중단. 기본 `true` |
| `tickets` | 예매 인원. 생략하면 `seats.min_consecutive` 사용 |
| `seats` | 좌석 위치 조건 (선택, `mode: cancel` + CGV 전용) |

### 반복 알림 (`repeat_alert_sec`)

기본 동작은 **새로 풀린 자리일 때 한 번만** 알리는 것입니다. 같은 자리가 계속
비어 있어도 다시 알리지 않으므로, 알림을 놓치면 그걸로 끝입니다.

`repeat_alert_sec: 60` 을 주면 조건에 맞는 자리가 열려 있는 동안 60초마다
다시 알립니다. 자리가 팔려서 사라지면 자동으로 멈춥니다.

```
🎟️ 취소표 발생! — 용산 IMAX 오디세이 취소표     ← 처음 발견
08/15(토) 18:00 · 오디세이 · IMAX관
잔여 2/624석 (신규 2석)
좌석: K17~K18

🔁 아직 열려 있음 — 용산 IMAX 오디세이 취소표    ← 60초마다 반복
08/15(토) 18:00 · 오디세이 · IMAX관
잔여 2/624석
좌석: K17~K18
```

반복 알림은 캐시된 좌석 정보를 쓰므로 **추가 요청이 발생하지 않습니다.**

### 날짜 (`dates`)

CGV가 상영일 목록을 내려주므로 날짜를 직접 적지 않아도 되고,
**새 날짜가 예매 오픈되면 자동으로 감시 대상에 들어옵니다** (목록은 10분마다 갱신).
새로 열린 날짜는 좌석이 통째로 비어 있으므로, 취소표를 기다리는 것보다
원하는 자리를 잡을 확률이 높습니다.

```yaml
dates: all                            # 예매 열린 상영일 전체
dates: {from: "20260810"}             # 그 날짜 이후 전부 (이후 열리는 날짜도 포함)
dates: {from: "20260810", to: "20260820"}
dates: ["20260805", "20260806"]       # 직접 지정
date: "20260805"                      # 단일 날짜
```

`to`를 비워두면 상한이 없어서 나중에 열리는 날짜도 계속 따라갑니다.
메가박스는 상영일 목록을 쓰지 않으므로 `date` 또는 `dates` 목록을 명시해야 합니다.

### 요일별 시간대 (`time_rules`)

```yaml
time_rules:
  weekday: ["19:00", "23:59"]   # 평일
  weekend: ["12:00", "20:00"]   # 주말·공휴일
```

토·일과 **공휴일**(CGV가 내려주는 `hldyYn`)은 `weekend` 규칙을 따릅니다.
한쪽만 적으면 나머지 요일은 시간 제한 없이 전부 봅니다.

CGV는 심야 상영을 `24:00`, `25:00`처럼 표기합니다 (25:00 = 다음날 새벽 1시).
평일 상한을 `23:59`로 두면 심야 회차가 빠지고, `26:00`으로 두면 포함됩니다.

### 좌석 위치 조건 (`seats`)

| 필드 | 설명 |
|------|------|
| `rows` | 감시할 열 `["F", "G", "H"]` (생략 시 전체 열) |
| `seat_no` | 좌석 번호 범위 `[4, 15]` (생략 시 전체) |
| `min_consecutive` | 나란히 붙어있어야 하는 최소 좌석 수 (기본 1) |

연속 여부는 같은 열 안에서 좌석 번호가 1씩 이어지는지로 판단합니다.
통로를 사이에 둔 좌석도 번호가 이어져 있으면 연석으로 봅니다.

`seats`를 생략하면 좌석 배치도를 조회하지 않고 잔여 좌석 "수"가 늘어날 때 알립니다.
좌석 배치도 조회는 해당 회차에 빈자리가 1석 이상일 때만 발생하므로,
매진된 회차를 감시하는 동안에는 추가 요청이 나가지 않습니다.

#### 알려진 한계 — API가 실제보다 낙관적입니다

좌석 API가 "판매가능"으로 내려주는 좌석 중 일부는 실제 좌석맵에서 선택할 수
없습니다. CGV의 **"1칸 외톨이 방지" 규칙** 때문입니다. 그 좌석을 잡으면
가장자리(통로 / 팔린 좌석 / 열 끝)와 내 좌석 사이에 정확히 한 칸이 고립되는
경우 프론트가 막습니다.

```
용산 IMAX관 2026-08-15 25:00 회차 실측
  API 판매가능 58석  vs  화면 선택가능 49석   (인원 1명)
```

좌석 레코드로는 구분할 수 없습니다 (`seatSaleYn`·`seatStusCd`·`stkndCd`가
막힌 좌석과 잡히는 좌석에서 전부 동일). 선택 인원수에 따라 달라지는 값이라
API가 정적으로 내려줄 수도 없습니다.

- **자동예매는 영향 없습니다.** 화면에서 `판매됨(disabled)`을 보고 건너뛴 뒤
  다음 후보 좌석으로 넘어갑니다.
- **알림은 과다 발생할 수 있습니다.** 못 잡는 자리로 알림이 갈 수 있습니다.
- `tickets: 1` 타겟은 **정확히 2칸짜리 고립 구간**을 아예 잡을 수 없습니다.
  어느 쪽을 잡아도 나머지 한 칸이 외톨이가 되기 때문입니다.
- `min_consecutive: 2` 이상을 거는 타겟은 대부분 자연히 걸러집니다.

자세한 내용과 대응 방안은 #13, #14 에 정리해 두었습니다.

## 자동 좌석 선택 (`auto_book`)

취소표를 발견하면 크롬을 몰아 **좌석을 선점하고 결제수단 화면까지** 진행한 뒤
멈춥니다. 결제는 하지 않습니다. 결제요청까지 보내려면 `auto_pay`를 함께 켭니다.

### 준비

평소 쓰는 크롬은 그대로 두고, 예매용 크롬을 하나 더 띄웁니다.

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --user-data-dir="$HOME/chrome-booking-profile" \
  --remote-debugging-port=9222
```

그 창에서 CGV에 한 번 로그인하면 프로필이 디스크에 남아 유지됩니다.

Playwright를 쓰지 않고 CDP를 직접 말합니다. 브라우저를 직접 띄우지 않으므로
`--enable-automation`이 붙지 않고 `navigator.webdriver`도 `false`로 유지됩니다.

극장·영화·날짜·회차·인원 클릭은 `Input.dispatchMouseEvent`로 보내 실제 입력과
구분되지 않습니다. **좌석만 예외로 `el.click()`을 씁니다** — 좌석맵은 600px
컨테이너에 약 1790px 콘텐츠를 담고 있어 대부분의 좌석이 화면 밖(x<0)에 놓이고,
좌표 기반 클릭으로는 누를 수 없기 때문입니다. 잡을 좌석의 `seatLocNo`를 이미
알고 있으므로 요소를 직접 찾아 누릅니다.

### 동작

```
/cnm/movieBook/movie → 극장 선택 → 영화 선택 → 날짜 → 회차
→ 인원 → 좌석 맵 열기 → 좌석 클릭 → 검증 → 정지
```

- **연석**: 인원이 2명 이상이면 첫 좌석만 누릅니다. CGV가 옆자리까지 자동으로
  잡아주므로, 좌석을 하나씩 누르면 오히려 그 동작과 충돌합니다.
  모자라면 그때만 추가로 누릅니다.
- **검증 게이트**: 좌석을 잡은 뒤 화면의 영화·상영관·날짜·회차·좌석 수가
  요청과 맞는지 확인하고, 어긋나면 거기서 멈춥니다. 셀렉터가 밀려 엉뚱한
  회차를 잡았을 때 그대로 진행하지 않게 하는 안전장치입니다.
- **동시 실행 방지**: 크롬 탭 하나를 몰기 때문에 한 번에 한 건만 진행합니다.
  겹치면 건너뛰고 다음 바퀴에 다시 잡습니다. 쿨다운은 두지 않습니다 —
  좌석은 약 5분이면 만료되므로 실패했으면 바로 다시 시도하는 편이 낫습니다.
- **낡은 목록 감지**: 날짜를 바꿔도 회차 목록과 좌석맵이 이전 날짜의 것으로
  남아 있는 경우가 있습니다. 그대로 진행하면 엉뚱한 회차를 잡거나, 실제로는
  빈자리인데 화면에서 "판매됨"으로 보여 아무것도 못 잡습니다. 화면의
  `N/624석` 표기와 좌석 버튼 수를 API 값과 대조해 어긋나면 중단합니다.
- **회차 지목**: 시작시간만으로 고르면 같은 시간대의 다른 상영관(1관 등)을
  누릅니다. 반드시 **상영관 이름까지** 맞춰서 지목합니다.
- **클릭 상한**: 인원 수보다 많이 누르지 않습니다. 더 누르면 CGV가
  "선택하신 관람인원은 N명입니다" 모달을 띄우고 이후 클릭이 막힙니다.
- **차단 모달 처리**: 좌석 클릭 후 뜨는 안내(휠체어 전용석, 인원 초과 등)를
  문구가 아니라 "확인/닫기만 있는 알림 모달" 형태로 감지해 닫습니다. 닫지
  않으면 모달이 화면을 덮어 이후 클릭이 전부 막힙니다.
- **휠체어 전용석 대체**: 좌석 조회 API는 휠체어 전용석도 `일반석`·판매 가능으로
  내려줘서 화면 안내로만 알 수 있습니다. 클릭 후 제한 안내가 뜨면 닫고 다음 후보
  좌석으로 넘어갑니다. (용산 IMAX관은 A17~A19, A22~A24가 해당)
- 폴링을 막지 않도록 별도 스레드에서 돕니다.

### 소요 시간 (실측)

예열은 두지 않습니다. 감시 중에 미리 페이지를 띄워두면 브라우저를 계속 헤집게
되고, 날짜가 넘어갈 때 낡은 목록을 잡는 문제가 생겨서 걷어냈습니다.
콜드 스타트 기준 좌석 선점까지 **약 6.9~8.0초**입니다.

```
① 페이지 로드          0.55 ~ 1.15s
② 극장 클릭            0.27s
③ 극장선택 확정        0.03s
④ 영화 클릭            0.10s
⑤ 회차목록 대기        0.17s
⑥ 날짜 클릭            0.19 ~ 0.36s
⑦ 회차 클릭 → 인원     ~1.0s
⑧ 인원 클릭            0.4 ~ 0.9s
⑨ 좌석맵 열기          0.25s
⑩ 좌석 클릭            ~1.0s
────────────────────────────────
   합계                6.9 ~ 8.0s
```

`BOOK_TRACE=1` 환경변수를 주면 단계별 시간이 로그에 찍힙니다.

### 한 번만 예매 (`auto_book_once`)

**기본값이 `true`** 입니다. **결제까지 완료되면** 그 타겟의 감시를 중단합니다.
알림도 오지 않습니다 — 표를 이미 샀으니 그 회차 취소표 소식은 의미가 없습니다.

```
결제 완료 — '용산 IMAX 오디세이 취소표' 감시를 중단합니다. 다시 감시하려면 재시작하세요.
```

**좌석 선점만 하고 결제하지 않은 경우는 중단하지 않습니다.** `auto_pay` 없이
`auto_book`만 켠 경우는 결제수단 화면에 도달해도 "결제 완료"가 아니므로 계속
감시합니다.

끄면(`false`) **표를 여러 장 살 수 있습니다.** 조건 구역이 넓을 때 이렇게 됩니다.

```
K~N열 16~29번 2연석 조건에서 4자리가 풀리면
  → 2장 결제
  → 남은 2자리가 여전히 조건 만족
  → 다음 바퀴에 또 발동 → 2장 더 결제
```

다시 잡게 하려면 `./launchd/manage.sh restart` 하거나 `auto_book_once: false`로
둡니다.

### 결제 화면까지 진행 (`auto_pay`)

`auto_pay: true`면 좌석 선택 뒤 결제 페이지까지 진행해 **카카오페이 승인 수단을
띄우고 멈춥니다.** 승인은 사용자가 폰에서 직접 합니다. 승인 없이는 결제되지 않습니다.

```
좌석 선택 → [선택완료] → [N원 결제하기] → 안내 모달 [결제하기]
→ /mpy/main → 카카오페이 선택 → 약관 동의 → [N원 결제하기]
→ online-payment.kakaopay.com
   · kakaopay 설정 있음 → 카톡결제로 결제요청 발송 → 승인 대기 → [확인] → 예매 완료
   · 없음               → QR결제 탭 표시 → 정지
```

### 승인 후 마무리 (`확인` 자동 클릭)

카톡결제는 폰에서 승인해도 **브라우저에서 `확인`을 눌러야 예매가 완료됩니다.**
승인 전에 누르면 `결제가 진행 중이에요` 모달이 뜨므로, 모달을 닫고 10초마다
다시 누르며 승인을 기다립니다.

이 클릭은 사용자가 **이미 결제를 승인한 뒤**의 마무리 단계입니다. 승인 없이는
아무리 눌러도 예매가 되지 않습니다.

`pay_timeout_sec`(기본 240초) 안에 승인되지 않으면 **놓친 것으로 보고 초기 화면으로
빠져나갑니다.** 결제 페이지에 머물러 있으면 좌석이 계속 묶여서 다른 사람도,
모니터도 그 자리를 볼 수 없기 때문입니다.

### 카톡결제로 받기 (권장)

**타겟별로** `kakaopay`를 채워두면 QR 대신 **카카오톡으로 결제요청이 옵니다.**
컴퓨터 앞에 없어도 폰에서 바로 승인할 수 있어서 QR보다 편합니다.

```yaml
targets:
  - name: "내가 결제할 타겟"
    kakaopay:
      phone: "01012345678"
      birth: "900101"      # YYMMDD 6자리

  - name: "환경변수로 받을 타겟"
    kakaopay: true         # CGV_KAKAO_PHONE / CGV_KAKAO_BIRTH 사용

  - name: "QR로 볼 타겟"
    # kakaopay 없음 → QR결제 탭
```

**전역 기본값은 없습니다.** 지정한 타겟만 카톡결제로 가고, 나머지는 QR입니다.
전역 폴백을 두면 의도하지 않은 사람에게 결제 요청이 갈 수 있습니다.
휴대폰번호와 생년월일 중 하나라도 비어 있으면 카톡결제를 시도하지 않고 QR로 갑니다.

한 예매에 여러 명에게 보내는 것은 불가능합니다. 예매 한 건이 결제 요청 한 건이고
승인한 사람이 결제합니다. 여러 명이 **알림**을 받는 것은 Discord/텔레그램 그룹으로
이미 됩니다.

**개인정보이므로 `config.yaml`이 `.gitignore`에 있는지 확인하세요.** 로그에는
`010******78 / 900*01` 처럼 마스킹해서 남깁니다.
환경변수 `CGV_KAKAO_PHONE` / `CGV_KAKAO_BIRTH`를 쓰면 파일에 남기지 않아도 됩니다.

어느 쪽이든 **최종 승인은 사용자가 폰에서** 합니다.

### 주의할 순서

**결제수단을 고르면 약관 체크가 초기화됩니다.**
약관을 먼저 체크하고 카카오페이를 고르면 `전체 약관에 동의해주세요`에서 막힙니다.
반드시 결제수단 → 약관 순서로 진행합니다.

금액은 막지 않고 로그에만 남깁니다. 카카오페이 승인 화면에 금액이 표시되고
사용자가 그것을 보고 승인하므로, 설정에 고정 금액을 두면 조조·심야처럼
가격이 다른 회차에서 정상 예매를 막게 됩니다.

### 좌석 선점 시간 (실측)

좌석은 고른 순간 서버가 잡고, **약 5분 뒤 자동으로 풀립니다.** 실측값입니다.

```
  0s  선점
142s  "결제 가능 시간이 2분 남았습니다. 5분 더 연장하시겠습니까?"
274s  "결제 가능 시간이 경과되어 좌석 선택 화면으로 돌아갑니다"
294s  좌석 해제 (API 잔여석 복구 확인)
```

그래서 `pay_timeout_sec` 기본값을 **240초**로 둡니다. 좌석 준비에 10초쯤
쓰이므로 실질 승인 가능 시간은 약 4분 30초입니다. 만료된 좌석을 붙잡고
기다리는 것은 의미가 없으므로 그 전에 빠져나와 좌석을 풀어줍니다.

**카카오페이 화면에 있는 동안은 CGV의 연장 알림을 볼 수 없습니다.**
같은 탭에서 CGV 페이지를 떠났기 때문입니다. 연장 처리(`_dismiss_timer`)는
CGV 페이지에 있는 단계에서만 동작합니다.

승인하지 못해 좌석이 풀리면 모니터가 다시 감지해 알립니다. 계속 시도하게
하려면 `auto_book_once: false` 로 둡니다.

### 알아둘 것

이 기능은 **로그인된 세션을 사용합니다.** 모니터 본체는 로그인을 하지 않아
최악이 IP 차단이지만, 이쪽은 계정이 얽힙니다. 성격이 다릅니다.

CGV UI가 바뀌면 깨집니다. 좌석 지목은 `data-seatlocno`(좌석 API의
`seatLocNo`와 동일)를 쓰고 인원·회차는 `aria-label`을 써서 빌드마다 바뀌는
CSS 모듈 해시 의존을 줄였지만, 그 앞의 클릭 체인은 여전히 취약합니다.

## 요청 수 관리

`max_requests_per_minute`는 **사이트별** 상한이며, 모든 요청(상영일 목록·스케줄·좌석
배치도)이 여기에 포함됩니다. 한 바퀴에 나가는 요청은 대략 이렇습니다.

```
감시 날짜 수 × 1 (스케줄)  +  빈자리가 있는 회차 수 × 1 (좌석 배치도)
```

요청을 줄이기 위해 세 가지가 적용됩니다.

- **매진 회차는 좌석 조회 없음** — `frSeatCnt`가 0이면 좌석 배치도를 부르지 않습니다.
- **잔여석 수가 그대로면 좌석 조회 없음** — 좌석이 팔리지도 취소되지도 않았다는 뜻이므로
  배치도를 다시 받지 않습니다. 수가 움직일 때만 조회합니다.
  단, 취소와 매수가 같은 바퀴에 상쇄되면 수가 그대로여도 좌석 구성이 바뀔 수 있어
  **5분마다는 강제로 다시 받습니다**(`SEAT_REFRESH_TTL`). 누락이 생겨도 최대 5분입니다.
- **미상영 날짜 건너뛰기** — 취소표 모드에서 조건에 맞는 회차가 하나도 없던 날짜는
  15분 동안 건너뜁니다. 상영이 시작되거나 시간표가 바뀌면 그때 다시 잡힙니다.
  (오픈 감시 모드는 아래 커서 방식이라 애초에 날짜를 하나만 봅니다.)
- **오픈 감시는 바퀴당 1회** — 아직 안 열린 가장 빠른 날짜 하나만 조회합니다.
  `dates`에 날짜를 10개 적든 20개 적든 요청 수는 바뀌지 않습니다.

덕분에 아무 변동이 없는 동안에는 스케줄 조회만 돌아 주기가 짧아지고,
좌석이 실제로 움직일 때만 배치도 조회가 붙습니다.

한 바퀴가 너무 길면 `dates`를 좁히는 쪽이 `max_requests_per_minute`를 올리는 것보다
안전합니다. 감시 대상이 줄면 요청 수와 주기가 함께 줄어듭니다.

## 실행

직접 띄우기:

```bash
mkdir -p ~/Library/Logs/cgv-monitor
nohup ./venv/bin/python -u main.py > ~/Library/Logs/cgv-monitor/monitor.log 2>&1 &
```

`-u`가 없으면 파이썬이 출력을 버퍼링해서 로그가 늦게 갱신되고,
워치독이 "모니터 멈춤"으로 오탐합니다.

로그 위치는 `~/Library/Logs/cgv-monitor/` 로 고정입니다. 워치독이 같은 경로를
보고 생사를 판단하므로 다른 곳으로 바꾸지 마세요.

### launchd로 상시 실행 (권장)

로그인하면 자동으로 뜨고, 크래시하면 자동으로 되살아납니다.
워치독도 5분마다 함께 돕니다.

```bash
./launchd/manage.sh install     # 설치 + 시작
./launchd/manage.sh status      # 동작 확인
./launchd/manage.sh logs        # 로그 실시간 보기
./launchd/manage.sh restart     # config.yaml 수정 후 반영
./launchd/manage.sh stop        # 중지 (모니터 + 워치독 함께)
./launchd/manage.sh uninstall   # 완전 제거
```

| plist | 역할 |
|-------|------|
| `local.cgv-monitor` | `main.py` 상시 실행. 비정상 종료 시에만 재시작 |
| `local.cgv-watchdog` | `watchdog.py`를 5분마다 실행 |

`KeepAlive`는 `SuccessfulExit: false`로 걸려 있어서, 모든 타겟을 감지하고
정상 종료한 경우에는 다시 띄우지 않습니다. 크래시했을 때만 되살아납니다.

**중지할 때는 `manage.sh stop`을 쓰세요.** 모니터만 따로 죽이면 워치독이
살아남아서 "모니터가 멈췄다"고 경보를 보냅니다.

`config.yaml`은 시작할 때 한 번만 읽으므로, 수정 후에는 `restart`가 필요합니다.

### 로그를 프로젝트 폴더에 두면 안 되는 이유

`~/Desktop`, `~/Documents`, `~/Downloads` 아래에 프로젝트가 있으면
launchd가 그곳의 **기존 로그 파일**을 stdout으로 열지 못하고
`EX_CONFIG (78)`로 죽습니다. 프로세스는 pid만 받고 아무것도 출력하지 못한 채
사라지므로 원인을 찾기가 어렵습니다.

```bash
launchctl print gui/$UID/local.cgv-monitor | grep "last exit"
#   last exit code = 78: EX_CONFIG
```

그래서 로그를 `~/Library/Logs/cgv-monitor/` 에 둡니다. 이 경로는 보호 대상이
아니라서 문제가 생기지 않습니다.

## 알림 설정

Discord와 텔레그램을 동시에 쓸 수 있습니다. 둘 다 비워두면 콘솔 출력만 됩니다.

### Discord

1. Discord에서 개인 서버 생성
2. 채널 설정 > 연동 > 웹후크 > 새 웹후크 > URL 복사
3. `config.yaml`의 `discord_webhook_url`에 붙여넣기
4. 서버 알림 설정을 "모든 메시지"로 변경하면 폰 푸시도 수신 가능

### 텔레그램 (폰 도달이 더 빠름)

1. 텔레그램에서 **@BotFather** 를 찾아 `/newbot` 을 보내고 봇 생성
   (아이디는 `_bot` 으로 끝나야 함) → 토큰 복사
2. 만든 봇과의 대화창을 열고 **아무 메시지나 한 번 전송**
   (봇은 먼저 말을 걸 수 없어서 이 과정이 꼭 필요합니다)
3. chat_id 조회 + 연결 테스트:

```bash
python3 telegram_setup.py <봇토큰>
```

4. 출력된 값을 `config.yaml`에 붙여넣기:

```yaml
notifications:
  telegram:
    bot_token: "123456789:AAH..."
    chat_id: "123456789"
```

### 채널별 발송 규칙

| 알림 | Discord 알림 웹훅 | Discord 하트비트 웹훅 | 텔레그램 |
|------|:---:|:---:|:---:|
| 취소표 발생 | ✅ | — | ✅ |
| 예매 오픈 감지 | ✅ | — | ✅ |
| 1시간 하트비트 | — | ✅ | — |
| 모니터 멈춤 경보 (워치독) | — | ✅ (`@here`) | — |
| 모니터링 종료 | — | ✅ | — |

**알림 웹훅과 텔레그램에는 예매 관련 알림만** 갑니다. 하트비트·장애 경보·종료 같은
모니터 운영 메시지는 전부 하트비트 채널로만 가므로, 알림 채널을 다른 사람과
공유해도 운영 잡음이 새지 않습니다.

`heartbeat_webhook_url`을 비워두면 운영 메시지도 알림 웹훅으로 폴백합니다.
